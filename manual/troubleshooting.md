# Troubleshoot a stopped or uncertain action

This guide is for the owner of the PC. Use it to find the first failed
check, decide whether work can resume and prepare a support bundle for
someone you choose. Use the manual for your verified release. If an
action is marked **Not yet available**, stop at that step.

## Find the first failed check

Open **Diagnostics** in the app. Read the result for the affected
site or installation and follow the check's stated fix. Save the
message together with its error code and the action you were taking.
If the app will not open, use the matching recovery help on your
verified installer media.

For a save, update or removal with an uncertain result, return to the
original action. Wait for its recorded check to show what happened
before making another request. If **Check files** identifies a missing
program file, use the verified repair offered for that file. An
unrecognised file needs your review.

If a provider refuses access, check the named connection and its
current status. Use its reconnect step only for the intended account
and scope. Older Search Console reports may still be visible if you
have access to them. After reconnecting, open the experiment and check
whether it can still use its sources. Reconnecting gives it no second
final check. A held upload needs its own check before you retry. Keep
the action paused when that result is unavailable.

If a XenForo site has a recent signed reply and SUT-340 still
appears, follow [the add-on reporting check][xf-reporting]. Use
the result for missed changes to check whether coverage has
returned. A successful connection check or PC repair alone
cannot verify those changes.

[xf-reporting]:
  site-administration.md#check-a-xenforo-add-on-reporting-warning

## Check ranking when the engine is unavailable

If SUT-800 says the engine is not answering, check the date on any
ranking history that is still available to you. It describes earlier
work. **Previous version restored** reports the app update result.
To check whether a ranking set was restored and is ready, reopen its
original job once the engine answers. Use that job's current result
before resuming affected work. If the check is unavailable, use the
matching local recovery guide and leave that work paused.

## Recover an optional DataForSEO lookup

For an uncertain charge, open the original lookup. The held amount
still counts against your budget. The final charge stays unknown
until a verified provider receipt matches the exact attempt. An
already verified acknowledgement charge appears separately. Keep
this request on hold. A new preview, request tag or credential cannot
send the same request again. Continue with the free local Coach or
eligible dated evidence.

| Code | What to do |
|---|---|
| SUT-6200 | Live data is unavailable. Check the original lookup result and continue with the local Coach or eligible saved evidence. |
| SUT-6201 | Billing is uncertain. Use the original lookup and keep the reservation as described above. |
| SUT-6202 | The lookup was refused before a payable plan. Review the option and market the app marks available. Any new payable plan needs its own price review and approval. |
| SUT-6203 | Live work is held. Check the named budget, pause, authority or expiry reason. Leave the request held while its required check fails. |
| SUT-6204 | The provider reply could not be used. Check the original lookup for its billing state. Use local checks or independently eligible saved evidence. |
| SUT-6205 | Provider page reading is unavailable. Leave that page reading on hold and use the local draft check. |
| SUT-6206 | This request is outside the current site or access. Check the intended site's connection and your current access before opening the lookup again. |

## Recover a Matomo timeline connection

Open the owner’s Matomo pane for the intended site and check its
last observed date and source time zone. A missing or unproved day
stays unknown. The app reads existing reports only. It cannot create
an archive for the missing day. Matomo search entries stay in their
own timeline pane. They give no verdict for an Update Lab study.

| Code | What to do |
|---|---|
| SUT-6300 | Setup was refused. Check the mapped site and the secure, unexpired View token from its dedicated non-admin account in the existing desktop setup. Review the exact mapping before approval. |
| SUT-6301 | The address was refused. Check the owner-controlled public HTTPS address, install path and certificate in the existing setup. Leave the connection held until its checks pass. |
| SUT-6302 | The report was unusable. Check the named report and whether the selected site has the expected archive in Matomo. Leave the rejected day unknown. |
| SUT-6303 | The archive for this day is unproved. The app does not query that day. Check the report's availability in Matomo and keep the day unknown until its archive proof passes. |
| SUT-6304 | The connector was revoked. Its jobs stop and its views become unavailable. Remove the old token in Matomo if it is still present. If you need a new connection, use the existing desktop setup to check the intended HTTPS address, Matomo site ID, time zone and a current restricted token, then approve the exact mapping. |
| SUT-6305 | Data is out of date after the automatic retry. Use the last eligible observed day if one is available. Otherwise there is no saved day. The failed day stays unknown. |
| SUT-6306 | The connector is paused. Check the named pause, disconnect or limit reason. Use the existing owner controls to resume only when offered and the current connection and permission checks pass. |

## Recover a saved site change

Open **Diagnostics** for the affected site. If SUT-308 says
“This release cannot read a saved site change”, the change history
is incomplete. Leave the site’s saved changes and earlier confirmed
records in place. Follow the verified recovery guidance for the
app and site add-on versions named by that check. A restart or a
successful connection check alone cannot clear this hold. Resume
affected work when the app verifies the original saved changes.

SUT-339 describes a gap in the saved changes. Follow its
reconciliation result separately. Keep the affected coverage marked
incomplete until the app verifies the missing work.

## Recover a start-up check

If SUT-934 says the settings migration table could not be verified,
keep the app stopped. Use the offline recovery help for the release
named by the failed start. Use its verified repair for the affected
package if offered. An old package or a manually replaced file
cannot satisfy the check. Start again after verification succeeds.

## If a model repair leaves suggestions on hold

If Model Hub offers a verified reinstall for MF-E12, review the
exact model revision. After reinstall, check the file result and
whether the ranking set is ready. MF-E09 means the model and its
required search index do not match. A verified file can still leave
new suggestions on hold. Follow the offered recovery for that set.
New suggestions can return when the matching set passes its checks.
You can still review earlier suggestions if they remain available to
you under their original result.

## Recover an interrupted crawl

Open the original crawl in **Jobs**. SUT-1601 means an incomplete
end of the crawl record was removed. The last verified progress
stays visible where your access allows it. If the last page check
is unconfirmed, leave it held and check its original recorded result.
An unconfirmed result does not allow a second fetch.

SUT-1602 means the app could not verify the committed crawl record.
Keep the affected crawl paused and use a verified recovery step if
offered. SUT-1615 means the crawl stopped for lack of storage. Review
the storage reason and use **Free up crawler storage** where offered.
Nothing is deleted to make space automatically. Resume only if the
original work and current permission, storage and request limits
can be verified. To remove protected copies use the existing removal
flow and wait for its receipt. A paused crawl does not prove removal.

## Check an unconfirmed audit export

If Site Health says “Export could not be confirmed”, open the
original CSV export for that site. If you saved it to an external
drive, check that the same approved drive is connected. Wait for
the app to verify the existing receipt. Leave the export on hold
while the app cannot check the destination. A previously verified
receipt records the earlier export. The app still needs a readable
destination to check the file now. Start another export for that
request only if the app confirms that the original file was never
written and offers its normal approval step.

If a removal check is waiting for the original Sutradhar-managed
copy, check its separate receipt. A disconnected drive leaves
removal unverified. Copies you already saved separately stay
in your custody.

## Prepare a support bundle

1. Open the support bundle preview. Check the site or installation
   shown and read what will be included. Select only the items needed
   to explain the fault.
2. Approve the exact preview you checked. If it expires or the selection
   changes, open a fresh preview. A bundle may contain check results,
   version details and scrubbed warnings. Use this preview to review
   the information before it leaves your PC.
3. Download the approved bundle. Keep its displayed file check value
   with it. If you decide to share it, choose the recipient yourself
   and use the protected route named by your release. A support bundle
   should never be put on a public issue or forum.

### If an approved bundle becomes unavailable

If the app stops delivery because access changed or it can no
longer verify which preview settings may be shared after a restore,
leave that bundle unavailable. Review a fresh preview only if the
app offers one.

If the bundle is affected by an erasure and the removal result is
unclear, open the original receipt in **Erasure**. An expired or
blocked download link tells you only that delivery through it has
stopped. If the managed file is still listed as **Waiting**, leave
that removal on hold until the app verifies what happened to the
original file. Reconnect the original approved drive if it is
missing. Any copy you already downloaded stays in your custody.
