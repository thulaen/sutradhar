# Configuration

This page is for owners who want to change a setting, choose a
resource budget or connect a local assistant or outside service.
It shows where to check the scope and outcome before saving. Use
the controls in your verified release and stop at an option marked
**Not yet available**.

## Check the scope of a setting

Select the intended site or installation and open the setting in
the app. Read its current value, proposed value and change summary.
Check whether it applies immediately or waits for a restart or job
boundary. Settings history shows what was saved. To check what the app
uses now, read the effective value for the current running service.
If the app says **Effective settings not yet verified**, leave held
work paused and read the current check before continuing.

For link suggestions, check the mode in use and the stage allowed by
the current verified ranking set. **Shadow** means the module can
run checks with its suggestions hidden. If a repair or reset saved
**Review** but the running mode is still **Shadow**, those suggestions
stay hidden. New eligible review suggestions can appear once review
is in use. Suggestions made in shadow stay hidden.

## Reset selected settings

Open **Factory reset that keeps data** from **Repair** if your
release offers it. Check the site or installation named in the
preview. Review the eligible caches and ordinary settings it lists.
For site settings, check the one site shown. The app removes only
the selected overrides. Each setting then takes its current preset's
value, or the built-in default when the preset has no value for it.
Read the values shown and confirm the exact plan in Repair. Your site
data, scripts, protected controls and settings history are kept.
Afterwards, check the effective values in the app.
If Repair says **Settings saved. Cache cleanup paused.**, check the
reason on the original reset. Open **Settings** to see which values
are in use and whether a restart is needed. Resume the original
cleanup only when Repair offers that action.

## Inspect what the engine uses

Open **Basic**, **Advanced** or **Engine Room** in the desktop app
for the level of detail you need. Select the site before reading a
setting, input, result or ranking method. The description shows
the source and scope. A reason beside a missing value tells you
when the evidence or your access is limited.

For a link suggestion, open its ranking explanation. Where you can
read the values, compare the original order value, the weight and
the adjusted value. Check the relevance decision and dated evidence
before using the result. The app can show whether a protected value
is present while keeping its content hidden.

## Set the PC's working budget

The memory screen offers **Safe**, **Balanced** and **Custom** where
the PC and release support them. Check the displayed memory limit
and available room on your PC. Custom stays within the allowed
range. A lower budget takes effect between jobs. It can make new
jobs wait while existing work finishes. The **Jobs** screen gives
the reason for a wait.

## Give a local assistant a limited role

Use the owner's **Agents** screen for an admitted local MCP
connection. MCP lets a connected assistant ask Sutradhar for an
allowed read or draft. Choose one site, the account and scopes,
and when access expires. Revoke access when it is no longer needed.

For an eligible agent settings change, review the exact plan and give
the live confirmation in the app. Confirmation applies once to that
plan. Protected settings, including controls that let site content
leave the PC, use their own owner route.

## Approve an outside service by purpose

Read what information the service receives, where it goes and any
cost before approving that exact route. Approvals for storage,
reports or a research provider have separate scopes. An offline or
refused request remains held until the relevant check passes. Use
the review shown for that provider before any paid use.

See [Reference](reference.md) for how to find the exact controls and
defaults for your release.
