# Using Sutradhar

This page is for owners who have set up a PC and connected a site.
It shows how to check whether a site is ready, follow work on the PC
and take a suggestion to the right reviewer. Use the manual that
matches your verified release. Leave any step marked **Not yet
available** until your release and site support it.

## Check the site before starting work

1. Open the desktop app and check that you have selected the intended
   site. Read its connection state and last contact. If the app shows
   old information, use it to see when the connection last worked.
2. Check that the site and the service are ready for the job you
   want to run. A running service can still have a site or module
   waiting for a check.
3. Check the **Jobs** screen. A waiting job may need more memory,
   a previous job to finish or an owner decision. Use the reason
   shown for that job. A delay gives no reason to start a duplicate.
4. If you use the portfolio and a site tile flags a stalled job,
   open that site and check its **Jobs** screen. The flag means a
   running job has gone without new progress for the configured
   time. If the tile's Jobs check is out of date or unavailable,
   check the job before starting the work again.

## Follow a suggestion from the PC to review

Sutradhar works from the eligible public content it has read from
the site. A suggestion can be waiting for more information. Check
its reason and coverage before using it. If too few suitable links
qualify, Sutradhar can show fewer suggestions.

Open the site's own review page to act on a suggestion. A moderator
checks the source, the words and the destination there. Version 1
does not insert links automatically. For review, pause and undo,
see [site administration](site-administration.md). For platform
save checks, see [WordPress safety](wordpress-safety.md).

## Check a draft in the Coach

1. Select the site and draft in the desktop Coach. Open the topic
   check, choose **Quick Search** or **Deep Research**, then select
   **Run**. Quick Search checks 8 to 15 practice questions. Deep
   Research checks 30 to 50. You can use local checks offline.
2. Choose a question to see the passage the Coach found. **Quotable**
   means the passage can answer the practice question on its own.
   **Weak or buried** means the answer could be clearer.
   **Missing** means the Coach found no suitable passage. Use the
   X-ray list to move between questions and passages. Start with
   questions that matter to your reader.
3. Check the evidence for the suggested next step. The Coach can
   suggest an answer here, an eligible page to link to or a topic to
   plan. Review any wording and make the changes in the editor.
   Practice questions and results describe a local check.

## Review an optional search lookup

1. Open **Keyword research** for selected terms or to expand one
   seed term. Open **Live search evidence** for other admitted
   results. Both are optional. If you connect DataForSEO, check
   the account and set a daily and monthly spending limit. Use
   **Test in free Sandbox** in the live evidence setup if offered.
2. Choose **Use saved evidence** to reuse an earlier result. Check
   its source, date and market. A search volume estimate describes
   demand. A Search Console impression records that your own site
   was shown. A missing figure stays unknown.
3. For a fresh lookup, open the review and check the exact terms
   or public address, market, other settings and maximum charge.
   The desktop owner approves the exact lookup. Editing or saving
   a draft uses local checks and saved evidence. The review explains
   what the provider receives.
4. If the app shows **Billing is uncertain**, open the original
   lookup result. The reserved amount still counts against your
   spending limit. The final charge is unknown. Keep the lookup
   on hold and continue with local checks or eligible saved
   evidence. See [paid lookup recovery][paid-lookup-recovery].

## Check a sitemap in Search Console

1. Check the exact site, Search Console property and sitemap address
   shown in Sutradhar. Resolve any unconfirmed property verification
   or owner access in Search Console before proceeding. A missing
   entry only tells you the available report did not show the sitemap.
2. Confirm that the site publishes the sitemap in a supported format.
   In Search Console, use live URL Inspection on the exact public
   sitemap URL. The sitemap must be accessible without a sign-in
   and **Page fetch** must show **Successful**.
3. In the same property, open **Sitemaps**. Paste the URL you just
   checked into **Add a new sitemap**, then select **Submit** there.
4. Check the processing status in Search Console. Open the sitemap's
   row if it reports an error. Sutradhar can show the outcome and
   observation date through its read-only connection.

[Google's Sitemaps report help](https://support.google.com/webmasters/answer/7451001?hl=en)

## Check a disavow file before using it

Use this option only for the exact Search Console URL-prefix
property with confirmed active proof of an unnatural inbound-link
manual action. Check the reviewed list and what the proposed
replacement keeps, adds or removes. An upload replaces the list
for the selected property.

Before using the file in Search Console, check the property,
manual action and current list again. A file prepared for HTTP
cannot be used for HTTPS. If the list changed, now exists where
you previously had none, or cannot be verified, do not upload
the old file. Supply current evidence and review a fresh
replacement in Sutradhar.

A local file or hand-off receipt records only what Sutradhar
prepared. Check any external result in Search Console yourself.
See the [official disavow instructions][disavow-help].

[disavow-help]: https://support.google.com/webmasters/answer/2648487?hl=en-GB

## Read the Google update timeline

1. Select the site and search surface, such as Web Search or Discover.
   Check the source for the chart and the official rollout dates.
   Crawling, indexing and serving notices have their own track.
   The seven-day wait applies to qualifying ranking rollouts. A
   service problem that affects a running experiment can put its
   results on hold. Open the experiment to see the reason.
2. During a rollout, give the charts time before making big changes.
   The tracker waits seven full days after Google confirms the end.
   It then needs enough final data for the chosen surface. If a page
   changed during the rollout, check its separate change marker.
3. When offered, select **Plan a study from this update** to review
   the own-site evidence and scope. Check the counts, time windows
   and exact scope before approving the study. In the Coach, open
   the evidence behind **Post-Update Winner Match** before using a
   suggestion. The match describes resemblance to pages that gained
   in a past comparison. Search outcomes can vary.

## Compare an approved staging export

When the staging comparison is available for this site, select the
site, staging project and approved page mapping. Use the file
picker to choose the approved local staging export. Review its
source and coverage against the selected saved live audit. The
staging file does not grant access to either site.

Use the admitted export for that project. A general site backup or
a staging URL cannot be used here. Leave passwords, login links and
private page copies out of the file. Sutradhar never logs in to
staging. If the file or mapping changes, choose the correct file
and review it again. If your access was withdrawn, ask the site
owner to review the scope before starting again. An earlier review
cannot restore access.

A missing page counts as absent only where the approved mapping
and complete observations prove it. An unread page stays unknown.
The comparison does not switch sites or apply a fix.

## Leave work in a known state

- Check the original job or action after a restart or lost connection.
  Its result tells you whether the work finished, is waiting or
  needs a further check. In Jobs, an earlier result belongs to the
  workflow version that ran. Restoring an older workflow opens a
  separate draft. If the original run is held, read the reason
  shown for that run.
- When **Ask for help** is available on the original job, review the
  preview, intended recipient and purpose before you approve it for
  manual copying or export. After a restart, check any reason shown
  on the original job. If a preview is out of date or its approval
  expired, review a fresh preview if offered. If its evidence was
  erased, leave that card unavailable. The app never sends it for you.
- On a normal installation, closing the window leaves the background
  service running. To stop the whole installation, use **Quit
  Sutradhar completely** and check the stopped state. A portable copy
  stops its service when the window closes.
- For an unavailable check or an uncertain result, see
  [Troubleshooting](troubleshooting.md). For backups, updates and
  removal, see [Operations](operations.md).
