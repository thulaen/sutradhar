## B. Choices inside those designs

1. Shared Dell administrator access (trust boundaries). Recommended: no
   account an agent can use keeps passwordless administrator rights, and
   you perform administrator steps yourself. Otherwise the separations
   guard against mistakes but not a hostile agent with administrator
   access.
2. Owner approval method. Recommended: a hardware security key signature
   (one touch per protected change). Alternative: a GitHub comment, only
   with the editing computer's GitHub access reduced to read-only.
3. Quota amount per charged failure (R093). Recommended 10; options 5, 25
   or 100. Debt grows additively; credit is not reset by a later failure.
4. Required AI review provider (R084, R057). Recommended: Claude Code's
   documented non-interactive mode; or Codex once its unattended route is
   qualified; or both.
5. Release preparation (R076). Recommended: Commitizen's local bump instead
   of Release Please.
6. Dependency updates (R076). Recommended: a weekly Dell dependency task
   instead of Dependabot pull requests, keeping Dependabot alerts.
7. If GitHub will not accept checks on an unreferenced commit (test Q1):
   allow one private non-branch candidate reference. This is the only
   fallback compatible with R084.
