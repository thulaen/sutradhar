# ADR-0005: Data and storage

Decided by the owner on 8 November 2026.

## Decision

- PostgreSQL, with row-level security forced on every table and an
  app role that cannot bypass it.
- Numbered plain SQL migrations applied by sqlx, with checksums, and
  checked by squawk.
- Durable jobs and the event outbox live in the same database.

The exact rules are in [AGENTS.md section 5.2](../../AGENTS.md#52-data).

## Why

- Row-level security makes the database itself refuse to show one
  site's data to another, even if our code has a bug.
- PostgreSQL has strong crash recovery and backups.
- Jobs and events in the same database share one transaction with the
  data they change, so there are no partial writes.

## Trade-offs

- PostgreSQL needs memory, and it counts within the memory limit.

## How we check it

- A check refuses any table without forced RLS, and an app role that
  owns tables or can bypass RLS.
- Tests prove one site cannot read another's rows.
- Tests kill the service mid-transaction and prove nothing half-written
  survives.
- Backup and restore are tested on every release.
